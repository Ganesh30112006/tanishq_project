============================================================
11. MULTI-USER SESSION ISOLATION
============================================================

This is a critical requirement.

The application must support multiple independent users.

Users may include:

- Patient A
- Patient B
- Doctor A
- Doctor B
- Lab Technician A
- Admin

Never allow state from one authenticated session to appear in another.

Implement:

- User-scoped application state
- User-scoped query/cache keys
- Permission-aware data fetching
- Session validation
- Cache invalidation on logout
- Sensitive state cleanup
- Patient-context cleanup
- Session expiration handling
- Authentication state reset

Example:

USER A
  ↓
Session A
  ↓
Patient A data

LOGOUT
  ↓
Clear sensitive state
  ↓
Invalidate relevant cache
  ↓
Reset patient context

USER B
  ↓
Session B
  ↓
Only authorized User B data

Never display stale User A data during the transition.

12. MULTI-TAB / MULTI-SESSION SAFETY
============================================================

Handle browser tabs safely.

- User should be redirected to authentication when appropriate

Do not leave previously loaded sensitive patient information visible after session invalidation.
